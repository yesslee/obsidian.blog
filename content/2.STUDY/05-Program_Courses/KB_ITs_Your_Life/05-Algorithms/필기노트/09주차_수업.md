# DP(Dynamic Programming)

큰 문제를 작은 문제들로 나누어 해결한 뒤, 그 결과를 **저장하여 중복 계산을 줄이는** 최적화 기법

→ 완전탐색, 재귀에서도 이런 방식이었다!

큰 문제를 작은 문제로 나누기 = DP 구현에 있어서 하나의 과정

포인트는 저장하여 중복 계산 줄이는 것!

1. 크고 복잡한 문제를 작은 문제들로 나눈다 → 작은 문제 = 하위 부분문제 = subproblem
    
2. 하위 문제의 답을 계산한다
    
    - 중복 계산해야하는 하위 문제가 존재 = 중복 하위 문제(overlapping subproblem)
        
        ⇒ 한 번 계산한 결과는 메모리에 저장하여 다시 계산하지 않도록 한다 = 메모이제이션(memoization, dp table)
        
3. 하위 문제에 대한 답을 통해 원래 문제에 대한 답을 계산한다 = 최적 부분 구조 = optimal substructure
    
    - 최적 부분 구조: 하위 부분문제에서 구한 최적의 답이 합쳐진 큰 문제의 최적의 답을 구할 수 있는 구조
    
    → 먹히는 문제, 안 먹히는 문제 구분 직관력 필요
    

피보나치 수열

→ 완전탐색(재귀) 대표적 예시였다!

DP를 활용한다면?

매번 재귀적으로 함수 호출해서 계산하지 말고 이전에 계산해둔 값을 메모리에 저장해두고 해당 값 가져다 더하자

⇒ 시간복잡도 $O(2^n)$ → $O(n)$으로 엄청나게 빨라진다!!!

피보나치 DP(메모이제이션) 구현 방법

hashmap 하나 만들어두고, n번째 계산 값 저장해두고 가져다 쓰자!

→ 아무도 계산하기 전이라면 가져다 쓸 수 있는게 없음

계산 결과 값 없다면 직접 계산해서 넣어주는 수밖에 없다

```java
Map<Integer, Integer> memo = new HashMap<>();

int fibo(int n) {
	if (n == 1 || n == 2) {
		return 1;
	}
	
	if (!memo.containsKey(n)) {
		memo.put(n, fibo(n - 1) + fibo(n - 2);
	}
	
	return memo.get(n);
}
```

어딘가에 저장한다 = DP table에 저장한다(보통 리스트에 넣어두는 편)

## DP 구현 방식

### Top-down

= memoization

재귀를 이용한 방식

원래의 큰 문제에서 작은 부분 문제로 내려가는 형태이기 때문에 top-down

```java
Map<Integer, Integer> memo = new HashMap<>();

int fibo(int n) {
	if (n == 1 || n == 2) {
		return 1;
	}
	
	if (!memo.containsKey(n)) {
		memo.put(n, fibo(n - 1) + fibo(n - 2);
	}
	
	return memo.get(n);
}
```

### Bottom-up

= tablation

반복문을 이용한 방식

가장 작은 부분 문제부터 원래의 큰 문제로 올라가는 형태이기 때문에 bottom-up

```java
Map<Integer, Integer> memo = new HashMap<>();
int fibo(int n) {
	memo.put(1, 1);
	memo.put(2, 1);
	
	for (int i = 3; i <= n; i++) {
		memo.put(i, memo.get(i - 1) + memo.get(i - 2));
	}
	
	return memo.get(n);
}
```
