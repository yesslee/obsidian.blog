
# OSI 7계층 & TCP / IP 4계층
- 논리적: OSI 7계층
- 실무적: TCP/IP 4계층

| ----- | --------------------- | ----------------------- | -------------- | --------------------------------------------------------- | --- | ----------------------------- |

하위
- 물리 계층(Physical)
	- 전기적, 기계적, 기능적 특성 이용
- 데이터링크 계층(Data Link)
	- **정확한 데이터 전달**
	- **오류제어**, **흐름제어** 등을 사용하여 정확한 데이터를 전달하는 것이 최우선 목표
	- Point-to-Point
- 네트워크 계층(Network)
	- 데이터를 쪼개 **패킷**을 만들어 **목적지까지 전달**
	- **라우팅** 역할, **혼잡 제어**, **패킷의 분할과 병합**
- 전송 계층(Transport)
	- **패킷**을 **순서대로 잃어버리지 않고** 다음 계층에 전달
	- **패킷 순서**, **흐름 제어**, **오류 수정** 중요 → 신뢰성, 정확성
	- 다중화(N:N)
- 세션 계층(Session)
	- 패킷 전달 개념에서 나아가 시스템, **프로세스 간 연결** 개념으로 확장
	- **통신 시스템 간 대화제어**, **연결 설정**, **프로세스 간 동기화 및 동기제어** 기능 수행
	- 응용 프로그램 간 접속 설정 및 유지
- 표현 계층(Presentation)
	- 응용 계층으로 보낼 데이터 번역기 역할
	- 세션 계층에서 받은 **데이터를 암호화/복호화**, **압축**, **구문 변환(아스키)** 등을 통해 응용 계층으로 전달
- 응용 계층(Application)
	- 사용자에게 보여지는 부분의 통신 담당
	- 사용자가 네트워크에 접근할 수 있는 **인터페이스와 서비스 제공**
	- 사용자와 직접적인 상호작용
상위
### 프레임 vs 패킷 vs 세그먼트
통신 과정에서 데이터는 계층별로 다른 단위로 포장 → 계층마다 명칭이 다름
- 데이터링크 계층 - 프레임(Frame)
- 네트워크 계층 - 패킷(Packet)
- 전송 계층 - 세그먼트(Segment, TCP) / 데이터그램(Datagram, UDP)

각 계층은 헤더를 붙여서 상위 계층의 데이터를 감싼다 → 캡슐화
- 상위 계층 데이터는 하위 계층의 페이로드가 되며 점점 더 구체적인 전달 정보를 갖춘 구조가 됨

# 프로토콜(Protocol)
> [!info] 프로토콜이란?
> 원거리에 있는 기계 사이에 정확한 데이터 송수신을 위한 통신규약

## 프로토콜 구성요소
- 구문(Syntax): 전송하고자 하는 데이터의 형식이나 부호화 및 신호 레벨에 대한 규정
- 의미(Semantic): 두 기기 간 효율적이고 정확한 정보 전송을 위한 협조 사항과 오류 관리를 위한 제어 정보에 대한 규정
- **순서(Timing)**: 접속되어 있는 개체(Entity) 간의 통신 속도 조정이나 메세지의 순서 제어 등을 규정

프로토콜의 기능
- **단편화(Fragmentation)**: 전송 블록을 같은 크기로 나누는 것 → [[#데이터 패킷의 조각화]]
- **재합성(Assembly)**: 수신 측에서 단편화된 데이터를 합쳐서 복원
- **캡슐화(Encapsulation)**: 어떤 프로토콜에서도 사용할 수 있는 블록이 될 수 있도록 제어정보 추가(사용자 정보 앞·뒤에 헤더와 트레일러 추가)
- 연결 제어(Connection Control): 비연결성, 가상회선을 이용한 통신로 개설, 유지, 종료
- 흐름 제어(Flow Control): 데이터 양, 통신 속도 등 수신 측의 처리 능력을 초과하지 않도록 제어
- 오류 제어(Error Control): 오류 검출 & 정정
- 순서 결정(Sequeucing): 데이터 순서대로 수신 측에 전달
- 주소 지정(Addressing): Destination Addr, Source Addr 처럼 정확한 주소 지정
- 동기화(Synchronization): 두 통신 개체 간의 상태 일치
- **다중화(Multiplexing)**: 한 통신로를 여러 가입자들이 동시에 사용
## 네트워크 프로토콜
### IP(Internet Protocol)
**IP의 특징**
- 비신뢰성(Unreliability)
- 비연결성(Connectionlessness)

**IP의 종류**
- 내부 IP
	- 데이터링크 계층에서 사용
- 외부 IP
	- 데이터링크 계층 → 네트워크 계층 이동 시 라우터를 통해 외부(WAN)로 묶여 나갈때 사용?
	- 외부 네트워크 대역을 엮는 것 = 라우터

> [!info] IP 주소란?
> 인터넷 상에서 통신하기 위해 각각의 컴퓨터 및 통신장비에 부여하는 고유한 주소

**IP 주소의 구성**
- 네트워크 주소 + 호스트 주소 로 구성
- **네트워크 주소**
	- IP 기기가 속해 있는 네트워크 구분에 사용
	- 클래스에 따라 네트워크 주소 부분의 크기가 변화
- **호스트 주소**
	- 네트워크 안에 있는 IP 기기 구분에 사용
	- 클래스에 따라 호스트 주소 부분의 크기가 변화

서브넷 마스크 = 어디까지가 네트워크이고 어디부터가 호스트인지 구분해주는 필터?

> [!memo] 네트워크 세팅
> IPv4: 172.17.100.49 → 나의 내부 IP
> subnetMask: 255.255.255.0 → 네트워크 대역을 sub 단위로 쪼갬
> router: 172.17.100.1 → 외부로 나갈 때 공인 IP 할당

#### IPv4
- 총 32비트, 8비트씩 4부분(옥텟)으로 10진수 표기
- **신뢰성 X, 전달만 함**
	- 중복된 패킷 전달, 패킷 순서 잘못 전달할 가능성 O
##### IP 주소 체계
- 유니캐스트(1:1)
- 멀티캐스트(1:N)
- 브로드캐스트(1:모든 N)
##### 헤더 구조
![[IPv4 헤더구조.png]]
- TTL(Time To Live): 라우터의 홉(Hop) 수
	- 라우터의 한 홉(Hop)을 통과할 때마다 TTL 값 1씩 감소
	- Ping(접근)과 Tracert(경로) 유틸리티는 특정 호스트 컴퓨터에 접근을 시도하거나 해당 호스트까지의 경로를 추적할 때 TTL 값 사용
		- 패킷의 루핑을 방지해서 미아가 되지 않도록 해주는 것이 포인트
##### IPv4 클래스
![[IP-classA.png]]
- 주소 범위: `0.0.0.0 ~ 127.255.255.255`
- 네트워크 ID: `1.0.0.0 ~ 126.0.0.0`
- 네트워크 수: 126개 (전체 128개 중 2개 제외)
	- `0.0.0.0/8`: 특수 용도로 예약된 범위
	- `127.0.0.0/8`: 루프백(loopback) 주소 범위
		- 자기 자신을 가리키기 위한 목적으로 예약된 IP 주소 범위
	⇒ 실제 네트워크 ID 부여 대상에서 제외
- 호스트 수: $2^{8} \times 2^{8} \times 2^{8} - 2 = 16,777,212$
	- 호스트 주소가 모두 0인 해당 네트워크 주소 1개와 호스트 주소가 모두 1인 해당 브로드캐스트 주소 1개 제외
- 서브넷 마스크: `255.0.0.0`
- 주요 용도: 국가 및 대형 네트워크
- 사설 IP 주소 범위: `10.0.0.0 ~ 10.255.255.255`

![[IP-classB.png]]
- 주소 범위: `128.0.0.0 ~ 191.255.255.255`
- 네트워크 ID: `128.0.0.0 ~ 191.255.0.0`
- 네트워크 수: $2^{6} \times 2^{8} = 16,384$
- 호스트 수: $2^{8} \times 2^{8} - 2 = 65,534$
	- 호스트 주소가 모두 0인 해당 네트워크 주소 1개와 호스트 주소가 모두 1인 해당 브로드캐스트 주소 1개 제외
- 서브넷 마스크: `255.255.0.0`
- 주요 용도: 중대형 네트워크
- 사설 IP 주소 범위: `172.16.0.0 ~ 172.31.255.255`

![[IP-classC.png]]
- 주소 범위: `192.0.0.0 ~ 223.255.255.255`
- 네트워크 ID: `192.0.0.0 ~ 223.255.255.0`
- 네트워크 수: $2^{5} \times 2^{8} \times 2^{8} = 2,097,152$
- 호스트 수: $2^{8} - 2 = 254$
	- 호스트 주소가 모두 0인 해당 네트워크 주소 1개와 호스트 주소가 모두 1인 해당 브로드캐스트 주소 1개 제외
- 서브넷 마스크: `255.255.255.0`
- 주요 용도: 소형 네트워크
- 사설 IP 주소 범위: `192.168.0.0 ~ 192.255.255.255`

##### 사설 IP
> [!info] 사설 IP란?
> 공인 IP를 사용하는 외부 네트워크 환경이 아닌, 내부 네트워크 환경에서 사용하도록 권장되는 내부 IP
> 외부망(인터넷망)에서 보이지 않으며, 그냥은 접속 불가> 

**권장 사설 IP 대역**
- A Class: `10.0.0.0 ~ 10.255.255.255`
- B Class: `172.16.0.0 ~ 172.31.255.255`
- C Class: `192.168.0.0 ~ 192.168.255.255`
⇒ 사용자가 망내에 있는 컴퓨터에 임의로 부여해도 되는 IP 주소이며, 
집이나 회사 내부에 있는 컴퓨터에 위의 사설 IP를 아무 주소나 할당하여 사용해도 문제 X
##### IP의 네트워크 주소 구하기
> [!question] Q. `211.203.50.130/26`의 네트워크 주소를 구하시오

**정석 풀이 방법**
1. IP 주소를 32비트 이진수로 변환한다.
	![[주소변환-1.png]]
2. CIDR 표기(`/숫자`)에 따라 앞에서부터 지정된 비트 수만큼 1로 채우고, 나머지는 0으로 채워 서브넷 마스크를 생성한다.
	![[주소변환-2.png]]
3. 이진수로 변환된 IP 주소와 서브넷 마스크를 각각 나열한 뒤 AND 연산을 수행한다.
	![[주소변환-3.png]]
4. AND 연산 결과를 다시 십진수로 변환하면 해당 IP 주소의 네트워크 주소가 된다.
	![[주소변환-4.png]]

**빠른 풀이 방법**
- AND 연산은 두 비트가 모두 1일 때만 결과가 1이 되므로,
  서브넷 마스크에서 각 옥텟(8비트)이 255인 경우(`11111111`) 해당 옥텟은 IP 주소 그대로 유지된다.
- 따라서, 서브넷 마스크에 0이 포함된 첫 옥텟 이후만 계산하면 빠르게 네트워크 주소를 구할 수 있다!
#### IPv6
- 총 128비트, 16비트씩 8부분(옥텟)으로 16진수 표기 (IPv4의 주소 공간을 4배 확장)
- 라우터의 부담을 줄여 네트워크 부하 분산
- 모바일 IP, IPSec 프로토콜 사용 가능
- 인증 및 보안 기능 강화
- 자동 주소 설정기능
- 확장 헤더를 사용해 안정된 옵션 사용 가능(헤더 자체도 더 단순)
- 0000 인 부분은 생략 가능
	- ex) `2001:0DB8:1000:0000:0000:0000:1111:2222` → `2001:0DB8:1000::::1111:2222`

##### IP 주소 체계
- 유니캐스트(1:1)
- 멀티캐스트(1:N)
- 애니캐스트(1:가장 가까운 1)

#### 데이터 패킷의 조각화
MTU(Maximum Transmission Unit)
데이터를 보낼 수 있는 최대 패킷의 크기

보내려는 데이터(Payload)가 2400이고 MTU가 980

각 패킷의 Payload 크기는 980 - 20 = 960

예시 문제

MTU: 980

몇 개의 패킷으로 쪼개지는가?
- 3개(960/960/459)
첫 번째 패킷의 데이터 크기는 얼마인가?
- 960
마지막 패킷의 데이터 크기는 얼마인가?
- 459

### ARP(Address Resolution Protocol)
> [!info] ARP란?
> IP 주소에 대응되는 MAC(Media Access Control) 주소를 알아내기 위한 프로토콜
> 네트워크 계층(IP)과 데이터링크 계층(MAC) 사이에서 동작

같은 네트워크(서브넷) 내에서 IP 주소를 알고있는 장치의 MAC 주소를 알아낼 때 사용
통신 대상이 다른 네트워크에 있는 경우, ARP는 해당 네트워크로 가는 기본 게이트웨이(라우터)의 MAC 주소를 알아내는데 사용

> [!tip] IP 주소와 MAC 주소
> **IP 주소 (Internet Protocol Address)**
> 네트워크 상에서 장치들이 식별되는 주소
> 논리적 주소로, 인터넷에서 데이터를 라우팅하고 전송하는 데 사용
> 
> **MAC 주소 (Media Access Control Address)**
> 네트워크 인터페이스 카드(NIC)에 부여된 물리적 주소, 각 장치를 고유하게 식별
> 주로 데이터링크 계층에서 사용되며, 로컬 네트워크에서 패킷 전송에 필요

#### ARP 동작 과정
- 요청: 브로드캐스트로 아무한테나 전송
- 응답: 유니캐스트로 단독으로 받음

![[ARP 프로토콜.png]]

> [!info] 스위치란?
> 어떤 디바이스가 스위치에 연결되면, 스위치는 이 디바이스의 MAC 주소를 기록
> 스위치는 기록된 MAC 주소를 사용해 어떤 디바이스가 외부 송출 패킷을 전송했는지, 전송된 패킷을 어디로 전달해야 하는지 파악
> 
> 내부 네트워크 대역을 엮음(LAN to LAN)

#### ARP 패킷 구조
![[ARP 패킷 구조.png]]
- Hardware Type: ARP 메시지를 전송할 때 사용하는 네트워크 계층의 하드웨어 유형
	- Ethernet: 1
	- IEEE 802: 6
	- HDLC: 17
- Protocol Type: 상위 계층의 프로토콜 유형(IPv4: 0x0800)
- Hardware Address Length: MAC 주소 길이(이더넷: 6)
- Protocol Address Length: 프로토콜 주소 길이(IPv4: 4)
- Opcode: 패킷의 유형을 정의
	- ARP request(요청): 1
	- ARP reply(응답): 2
	- RARP request(요청): 3
	- RARP reply(응답): 4
- Sender Hardware Address(6 Bytes): 송신자의 MAC 주소
- Sender IP Address(4 Bytes): 송신자의 IP 주소
- Target Hardware Address(6 Bytes): 타겟의 MAC 주소
	- Request 요청시에는 비워둠!
- Target IP Address(4 Bytes): 타겟의 IP 주소

> [!info] ARP & RARP
> - ARP: IP 주소에 대응되는 MAC 주소를 알아내는 프로토콜
> - RARP: MAC 주소에 대응되는 IP 주소를 알아내는 프로토콜

#### ARP 캐시
- ARP 통신을 통해 얻은 IP 주소와 MAC 주소의 매핑 정보를 일시적으로 저장하는 공간
- 향후 통신에서 중복된 ARP 통신을 방지하여 효율적인 데이터 전송

### 라우팅 프로토콜
#### RIP(Routing Information Protocol)
- 거리 벡터(Distance Vector) 라우팅 프로토콜, 홉 수(Hop Count)를 기준으로 경로 선택
- 최단 경로 탐색에 Bellman-Ford 알고리즘 사용

특징
- 최대 15홉까지의 네트워크만 지원 ⇒ 대규모 네트워크에는 부적합
- 거리 벡터 방식: 각 라우터가 자신의 경로에 대한 정보를 이웃 라우터에만 전송, 경로 정보는 여러 라우터를 거쳐서 전파
- 30초마다 라우팅 정보 갱신
- 단순한 구조로 소규모 네트워크에서 주로 사용
  (최대 홉수 15로 제한되어 대규모 네트워크에는 적합하지 않음)
- 표준 프로토콜 → 대부분의 라우터가 지원
- RIPv1은 브로드캐스트, RIPv2는 멀티캐스트를 이용하여 광고
#### OSPF(Open Shortest Path First)
- Link State 라우팅 프로토콜
- 최단 경로 탐색에 Dijkstra 알고리즘 사용

특징
- RIP와 달리 홉 수 제한 X ⇒ 대규모 네트워크에 적합
- 네트워크 내의 모든 라우터가 링크 상태 광고(LSA: Link State Advertisement)를 통해 전체 네트워크 상태를 파악하고 최단 경로 계산
- 네트워크 상태에 변경이 생기면 즉시 라우팅 테이블을 갱신
- 복잡한 구조로 중대형 네트워크에 적합한 프로토콜
	- 효율적이고 확장성 있는 라우팅 제공

### ICMP(Internet Control Message Protocol)
네트워크 통신을 할 때 운영체제로부터 오류 메시지를 알려주는 프로토콜

| Type | Message                 | 설명                                  |
| ---- | ----------------------- | ----------------------------------- |
| 0    | Echo Reply              | 핑(Ping) 응답 (에코 요청에 대한 응답)           |
| 3    | Destination unreachable | 전송 했으나 목적지 도달 X (클라이언트 단에서 확인 필요)   |
| 4    | Source quench           | 전송 흐름 제어                            |
| 5    | Redirection             | 더 나은 경로로 라우팅 제안                     |
| 8    | Echo Request            | 핑(Ping) 요청 (네트워크 연결 확인)             |
| 11   | Time To Live Exceeded   | 전송 했으나 TTL 초과로 패킷 소멸 (서버 단에서 확인 필요) |
| 12   | Parameter Problem       | 잘못된 IP 헤더 정보로 발생한 에러                |
| 13   | Time Stamp Request      | 지연시간 정보 요청                          |
| 14   | Time Stamp Reply        | 지연시간 정보 응답                          |
| 17   | Address Mask Request    | 서브넷 마스크 요청                          |
| 18   | Address Mask Reply      | 서브넷 마스크 응답                          |

### IGMP(Internet Group Management Protocol)
인터넷에서 멀티캐스트를 위해 사용되는 프로토콜
IPv4를 사용하는 네트워크에서 멀티캐스트 설정에 사용되는 프로토콜
여러 장치가 하나의 IP 주소를 공유하여 모두 동일한 데이터 수신 가능
TTL 제공되는 비대칭 프로토콜

## 전송 프로토콜
### UDP(User Datagram Protocol)
전송 계층(Transport)의 **비연결성** 프로토콜, IP를 가지고 연결된 포트 기반으로 통신

특징
- 패킷 순서 보장 X
- 손실의 위험이 있어 신뢰성 낮음
- 빠른 전송 속도

오류 및 에러 검사를 하지 않아도 되는 데이터를 보낼 때 적합
- 실시간 채팅, 메신저
- 동영상 스트리밍, 화상 통화

#### UDP 헤더 구조
![[UDP 헤더구조.png]]
- 헤더 비교적 간단한 편 → 신뢰성 낮음(최소한의 오버헤드?)

### TCP(Transmission Control Protocol)
전송 계층(Transport)의 **연결성** 프로토콜, 가상회선 방식 사용

흐름제어
- Sliding Window: 확인 신호를 이용하여 송신 데이터 양 조절
- Stop and Wait: 프레임 하나씩 응답 유무에 따라 재전송 여부 결정

특징
- UDP보다 복잡
- 느린 전송 속도
- 높은 신뢰성
- 연결이 되어있는 상태에서만
- 일대일 통신만 가능(Point-to-Point)
#### TCP 헤더 구조
![[TCP 헤더구조.png]]
- Source Port / Destination Port: 세그먼트의 출발지와 목적지를 나타내는 필드
- Sequence Number: 전송하는 데이터의 순서
- Ackknowledgement Number: 수신 측이 예상하는 다음 시퀀스 넘버?
- Control Flags: 세그먼트의 상태를 나타내는 비트 플래그
	- URG(긴급, 최우선)
	- ACK(확인)
	- PSH(푸시)
	- RST(리셋)
	- SYN(요청)
	- FIN(완료)
- Window Size: 한 번에 전송할 수 있는 데이터의 양
- Check sum: 송신 중에 발생하는 오류 검출 값(값 대조하여 검출)

#### 3-way Handshake
TCP는 서로 연결되어 있는 상태에서만 통신 가능
서로 통신할 준비가 되었는지 확인하는 과정이 3-way Handshake?

TCP/IP 프로토콜을 이용해서 통신을 하는 응용프로그램이 데이터 전송 전에 정확한 전송을 보장하기 위해 상대방 컴퓨터와 사전에 세션을 수립하는 과정

TCP 연결 초기화시 수행(4-way Handshake는 TCP 세션 종료시 수행)


Client → Server
클라이언트는 서버에 접속 요청하는 SYN 플래그를 헤더에 담아서 패킷 전송
클라이언트는 서버의 SYN+ACK 응답을 대기하는 SYN_SENT 상태가 됨

Server → Client
서버는 클라이언트의 SYN 요청을 받았고 클라이언트의 요청 수락한다는 SYN+ACK 플래그를 헤더에 담아서 패킷 전송
서버는 클라이언트의 ACK 응답을 대기하는 SYN_RECEIVED 상태가 됨

Client → Server
클라이언트는 서버에 확인 답장 ACK 플래그를 보냄
이후 연결이 이루어지고 데이터 오가게 됨
클라이언트와 서버 상태는 ESTABLISHED → 이 상태일때 통신 가능?

#### TCP State
서버
- 항상 listen 상태여야함
- 수동적(passive)

### 응용 프로토콜
주로 응용 계층(Application Layer)에서 작동

### HTTP
클라이언트와 서버 사이에 이루어지는 요청/응답(request/response) 프로토콜
주로 HTML 문서를 주고받는데 사용
포트넘버 80

### HTTPS
HTTP 보안 강화 버전
소켓 통신에서 일반 텍스트 대신 SSL이나 TLS 프로토콜을 이용해 세션 데이터를 암호화하여 데이터의 적절한 보호 보장

TFTP(Trivial File Transfer Protocol)
UDP 기반
간단한 파일 전송을 위한 경량 프로토콜
FTP보다 제한적 기능 / 빠른 속도
주로 네트워크 Bootstraping과 라우터 설정 등에 사용
인증 기능 X, 익명 접속만 허용 ⇒ 보안성 취약, 데이터 암호화 되지 않아 도청 위험
포트넘버 69

FTP(File Transfer Protocol)
TCP/IP 기반
파일 및 디렉토리 전송 및 관리에 사용
인증 필요, 사용자 계정과 비밀번호로 접속
명령 채널과 데이터 채널 사용하여 제어와 데이터 전송 분리 ⇒ 데이터 전송(20), 제어(21)
⇒ 보안성 취약, 데이터 암호화 되지 않아 도청 위험?


Telnet
네트워크 상에서 다른 컴퓨터에 원격 로그인 하거나 원격으로 명령을 실행하기 위한 프로토콜
특정 서버 연결에 문제가 없는지, 접근이 가능한지 확인할 때 주로 사용
TCP/IP 기반
최근에는 보안상의 이유로 Telnet 보다 SSH 사용 ⇒ 통신 암호화 X 보안 취약 스니핑 위험
포트넘버 23


SSH(Secure Shell)
네트워크 상의 다른 컴퓨터에 로그인하거나 원격 시스템에서 명령을 실행하고 다른 시스템으로 파일을 복사할 수 있도록 해주는 프로토콜
주고받는 데이터 자체가 암호화되어 해당 패킷이 스니핑 되더라도 복호화할 수 있는 key를 얻지 못하면 해당 정보를 알 수 없게끔 설계
포트넘버 22


DHCP(Dynamic Host Configuration Protocol)
호스트의 IP 주소와 각종 TCP/IP 프로토콜의 기본 설정을 클라이언트에게 자동으로 제공해주는 프로토콜
네트워크 안의 컴퓨터에 자동으로 네임서버주소, IP주소, 게이트웨이 주소를 할당하고 해당 클라이언트에게 일정기간 임대하는 동적 주소 할당 프로토콜
PC 수가 많거나 PC 자체 변동사항이 많은 경우 자동으로 IP 설정 해주기 때문에 효율적 사용 및 IP 충돌 방지 가능
DHCP 서버에 의존적이기 때문에 서버 다운되면 IP 할당 X

### DNS(Domain Name System)
웹사이트 주소를 입력하면 브라우저가 DNS 서버에 요청
UDP & TCP 둘 다 사용 가능한 프로토콜
- UDP: Default
- TCP: 패킷 512 bytes 이상인 경우 사용
포트넘버 53
### SNMP(Simple Network Management Protocol)
네트워크 장비를 원격으로 관리 및 감시하는 프로토콜

UDP 데이터그램 사용해서 전송
IETF RFC1157 표준 권고안
4가지 기능만 수행
- GET
- GET NEXT
- SET
- TRAP
비동기식 요청/응답 메시지 프로토콜
포트넘버 161, 162

### SMTP(Simple Mail Transfer Protocol)
전자 메일을 발신할 때 사용되는 프로토콜

포트 넘버 25

## 에러 종류와 원인
감쇠현상: 전송신호가 전송매체를 통과하며 신호 세기 약화(아날로그 - 증폭기 / 디지털 - 리피터)
지연왜곡
신호전달이 주파수에 따라 속도가 달라져 신호 손상 유발
잡음
- 열잡음: 모든 진동 스펙트럼을 포함한 잡음
- 충격잡음: 순간적인 높은 진폭의 잡음
- 누화잡음: 상호인접한 전송매체의 전자기적 상호 유도 작용으로 인한 잡음
- 상호변조잡음: 서로 다른 주파수들이 똑같은 전송매체를 공유할 때 주파수 신호 차이로 발생
에코: 선로상 임피던스의 변화가 있을 때, 약해진 신호가 송신 측으로 다시 돌아옴
위상지터: 연속적으로 위상이 변해 편차가 커지며 발생

## 전송 에러 제어 방식
- 반복전송방식
	- 송신측: 동일 데이터를 2번 이상 연속 전송
	- 수신측: 수신된 데이터 비교하여 오류 여부 확인
궤환전송방식: 송신측으로 궤환(echo)된 데이터를 비교 및 검사 → 2번 이상의 전송 필요(전송요량의 낭비 발생)
전진오류수정(FEC)
- 송신측: 정보비트 + 부가코드 함께 전송
- 수신측: 부호로 오류 검출 및 수정(해밍 코드, 순환중복검사(CRC))
후진오류수정(BEC): 전송과정에서 오류발생시 수신측에서 재전송 요구(ARQ)

### 에러 검출 방식
패리티 검사: 전송되는 문자마다 +1개의 패리티 비트를 추가하여 EVEN/ODD 검사

순환중복검사(CRC)
블록마다 +검사용 코드 추가해서 전송
데이터를 연속하여 전송하는 경우 집단오류검출을 위해 사용
주로 동기식 전송에서 주로 사용

해밍 코드 방식
에러 검출 & 교정(수정) 가능한 코드, 자기정정부호의 하나로 비트 착오를 검출 → 1비트 착오 정정
고속 동기식 전송에서 사용

### 에러 수정 방식(ARQ: Automatic Repeat Request)
Stop and Wait ARQ
송신측: 블록 전송 후 수신측의 응답(ACK/NAK) 대기

Go back-N ARQ
송신측: 여러 블록 연속해서 전송한 뒤 수신측에게 NAK 받으면 에러 발생한 블록 이후의 모든 데이터 재전송

Selective-Repeat ARQ
송신측: 여러 블록 연속해서 전송한 뒤, 수신측에게 NAK 받으면 에러가 발생한 블록만 선택하여 재전송

Adaptive ARQ
전송효율을 높이기 위해 블록 길이를 동적으로 변경하여 전송
## 토폴로지(Topology)
> [!info] 토폴로지란?
> 컴퓨터 네트워크의 요소들(링크, 노드 등)을 물리적으로 연결해 놓은 방식
### 토폴로지의 종류
![[토폴로지.png]] 

**Bus Topology (버스형)**
- 구조: 하나의 중앙 통신 선로(버스)를 모든 노드가 공유
  → 터미네이터로 시그널 반사 방지
- 장점
	- 구조 단순, 낮은 설치비용
	- 단말기 추가/삭제 용이
- 단점
	- 중앙 케이블 오류 시 전체 네트워크 마비
	- 충돌 발생 가능성 높음
	- 확장성 제한

**Star Topology (스타형)**
- 구조: 중앙 허브나 스위치에 모든 노드가 개별적으로 연결
  → 중앙집중형 구조
- 장점
	- 한 노드의 장애가 전체 네트워크에 영향 X
	- 관리 및 문제식별 용이
- 단점
	- 중앙 장비(허브/스위치) 장애 시 전체 마비
	- 설치 시 많은 케이블 필요 → 설치 비용 증가

**Ring Topology (링형)**
- 구조: 노드들이 고리 형태로 단방향 또는 양방향 연결
- 장점
	- 데이터가 한 방향으로 흐르므로 충돌 적음
	- 일정한 지연 시간 제공
	- 양방향 연결 시 통신회선 장애에 대해 유연
- 단점
	- 노드 하나 장애시 전체 통신 단절 가능
	- 노드 추가/제거 번거로움

**Tree Topology (트리형)**
- 구조: 스타형과 버스형 혼합의 계층적 구조
  → 분산 처리 시스템 구성에 적합
- 장점
	- 대규모 네트워크에 적합
	- 관리 및 확장 용이
- 단점
	- 루트/상위 노드 장애 시 하위 노드 전체 영향
	- 구성 복잡도와 설치 비용 증가

**Mesh Topology (메쉬형)**
- 구조: 모든 노드가 서로 직접 연결(Fully Connected)
  → 공중 데이터 통신망 등에서 주로 사용
- 장점
	- 높은 신뢰성, 장애 허용성
	- 노드 간 최단 경로 선택 가능
- 단점
	- 연결 수 많아 설치 복잡, 높은 비용
	- 유지보수 어려움

## IEEE 802
근거리 통신망과 도시권 통신망을 관할하는 전지 전자 기술자 협회(IEEE) 표준 규칙들의 계열

IEEE 802.1 - 상위 계층 인터페이스와 MAC BRIDGE
**IEEE 802.2 - LLC(Logical Link Control)**
**IEEE 802.3 - CSMA/CD (Carrier Sense Multiple Access/Collision Detection)**
**IEEE 802.4 - 토큰 버스(Token Bus)**
**IEEE 802.5 - 토큰 링(Token Ring)**
IEEE 802.6 - MAN(Metropolitan Area Network)
IEEE 802.7 - 광대역(Broadband) LAN
IEEE 802.8 - 광섬유(Fiber Optic) LAN
IEEE 802.9 - 종합 데이터 & 음성 네트워크
IEEE 802.10 - 보안(Security)
**IEEE 802.11 - 무선 네트워크(Wireless Network), CSMA/CD**

### CSMA/CD
> [!info] CSMA/CD
> 이더넷 네트워크에서 데이터 충돌을 방지하고 해결하기 위한 프로토콜
> 
> - CS(Carrier Sense): 프레임 전송 전에 현재 전송 중인 프레임이 있는지 확인
> - MA(Multiple Access): 전송할 프레임을 가진 모든 이더넷 장비는 프레임 전송 가능
> - CD(Collision Detection): 프레임 전송 후 항상 충돌 발생 여부 확인
> 
> CSMA/CD는 이더넷 표준의 일부로 남아있지만, 스위칭 허버의 등장으로 충돌 발생 빈도가 현저히 줄어들었음
> 무선 네트워크에서는 충돌 감지가 어렵기 때문에 CSMA/CD 방식 사용

## 이더넷(Ethernet)
> [!info] 이더넷이란?
> 유선 LAN(근거리 통신망)에서 가장 널리 사용되는 기술 규격
> 물리 계층(신호, 배선)과 데이터 링크 계층(MAC, 프레임)을 정의하며, IEEE 802.3 표준을 기반으로 함
### 이더넷 프레임 구조
![[이더넷 프레임 구조.png]]
- Preamble: 수신 동기화를 위한 비트열
	- 56 bit 동안 1과 0ㅇ을 반복 (`10101...`)
- SFD (Start Frame Delimiter): 프레임 시작을 알리는 구분자 (`0xAB`)
	- 마지막 두 비트가 11(`0xAB = 10101011`)
- Destination Address: 도착지 MAC 주소
- Source Address: 출발지 MAC 주소
- Length/Type: 전송되는 데이터의 길이 또는 상위 계층 프로토콜 식별자
	- 0x600 이하면 Length (IEEE 802.3) 로 해석
	  → 수납되는 LLC 프레임 길이(3 ~ 1500 byte)
	- 0x600 이상이면 Type 으로 해석
	  → Data에 담겨있는 상위 프로토콜
		- EtherType(이더넷 타입)
			- `0x0800`: IPv4
			- `0x0806`: ARP
			- `0x8100`: Ethernet
			- `0x86dd`: IPv6
- Data & Padding: 실제 데이터 (LLC 등 포함) 및 최소 프레임 길이를 위한 패딩 포함
- FCS (Frame Check Sequence): 오류 검출을 위한 CRC 값
### 이더넷 전송 규격

#### 10BASE-T
- 이름: Ethernet
- 표준: IEEE 802.3
- 전송 속도: 10 Mbps
- 전송 방식: 기저대역(Baseband)
- 전송 모드: Half Duplex 또는 Full Duplex
- 전송 매체: UTP Cat.3 이상
- 케이블 쌍 수: 2쌍 (송수신 각각 1쌍)
- 대표 토폴로지: 스타형(물리), 버스형(논리)
- 세그먼트 최대 길이: 100m
- 기타 특징:
	- 초기 이더넷 표준
#### 100BASE-T
- 이름: Fast Ethernet
- 표준: IEEE 802.3u
- 전송 속도: 100Mbps
- 전송 방식: 기저대역(Baseband), CSMA/CD 사용
- 전송 모드: Half Duplex 또는 Full Duplex
- 전송 매체 및 종류:
	- 100BASE-TX: UTP Cat.5 또는 STP 사용 (가장 일반적)
	- 100BASE-T2: UTP Cat.3 이상
	- 100BASE-T4: UTP Cat.3, Cat.4, Cat.5 (4쌍 중 3쌍 사용, 현재는 거의 사용 X)
- 케이블 쌍 수: 2쌍 (TX: 송신 1쌍, 수신 1쌍)
- 대표 토폴로지: 스타형
- 세그먼트 최대 길이: 100m
- 기타 특징:
	- 가장 널리 사용된 구내 통신망 규격 중 하나
	  (현재는 대부분 1000BASE-T 이상으로 전환)
#### 1000BASE-T
- 이름: Gigabit Ethernet
- 표준: IEEE 802.3ab
- 전송 속도: 1 Gbps(= 1000 Mbps)
- 전송 방식: 기저대역(Baseband), PAM-5 (5레벨 펄스 진폭 변조)
	- 4쌍(8가닥) 모두를 사용하여 각 쌍당 250 Mbps 전송
- 전송모드: Full Duplex
	- 송수신을 동시에 처리 (Echo cancellation 기법 활용)
- 전송 매체: UTP Cat.5e 이상
- 케이블 쌍 수: 4쌍 모두 송수신용
- 대표 토폴로지: 스타형
- 세그먼트 최대 길이: 100m
- 기타 특징:
	- 허브 보다는 스위치 기반 환경에서 주로 사용
	- 높은 속도와 안정성으로 현재 가장 일반적인 LAN 표준

## DNS(Domain Name Server)
DNS 레코드
서버가 요청에 응답하는 방법에 대한 다양한 구문과 명령 포함
어떤식으로 처리할 지 나타내는 지침

| DNS 레코드 | 설명                                                |
| ------- | ------------------------------------------------- |
| A       | 도메인 이름 → IP 주소 매핑(IPv4)                           |
| AAAA    | IPv6 버전의 A 레코드<br>도메인 이름 → IP 주소 매핑(IPv6)         |
| CNAME   | 별칭을 부여한 특정 도메인 주소                                 |
| MX      | 메일 서버 지정(메일을 주고받기 위한 서비스 레코드)                     |
| SOA     | 도메인의 시작점(zone 파일의 시작 레코드)                         |
| PTR     | IP 주소 → 도메인 이름 매핑(역방향 조회)<br>reverse zone 파일에서 사용 |

TTL(Time To Live): DNS Caching 수명
- DNS 레코드가 캐시에 유지되는 시간
- TTL 값이 길면 DNS 부하 감소

## HTTP 상태 코드
### 2XX - Success
- **200 OK**: 서버가 요청을 성공적으로 처리
- **201 Created**: 요청 처리되어 새로운 리소스가 생성
- **202 Accepted**: 요청은 접수했지만 처리 완료는 X
### 3XX - Redirection
- 300 Multiple Choices: 다중 선택 항목(서버에서 콘텐츠 결정하지 못하고 클라이언트에게 복수 개 링크 응답할 때 사용)
- **301 Moved Permanently**: 지정한 리소스가 새로운 URI로 이동
- 302 Found: 요청한 리소스 다른 URI에서 발견(의미 개선하여 307 정의하였기에 해당 코드 사용 권장 X)
	- 307 Temporary Redirect: 임시로 리다이렉션 요청 필요
- **303 See Other**: 다른 위치로 요청하라
  Location에 표시된 URI에서 GET으로 취득 가능
  브라우저의 form 요청을 POST로 처리하고 결과하면으로 리다이렉트 시킬 때 자주 사용
### 4XX - Client Errors
- **400 Bad Request**: 요청 구문이 잘못됨
- **401 Unauthorized**: 지정한 리소스에 대한 접근 권한 X
- 402 Payment Required: 지정한 리소스에 대해 접근하기 위해서는 결제 필요
  실제로는 사용 X
- **403 Forbidden**: 지정한 리소스에 대한 접근 금지됨
	- 401 이외의 사유로 리소스에 대한 접근 금지됨을 의미
- **404 Not Found**: 지정한 리소스를 찾을 수 없음
### 5XX - Server Errors
- **500 Internal Server Error**: 서버에 에러 발생
- **501 Not Implemented**: 요청한 URI 메소드가 서버에 구현 X
- **502 Bad Gateway**: 게이트웨이 또는 프록시 역할 서버가 뒷단 서버로부터 잘못된 응답 받음

# 네트워크 운용기기
## RAID
> [!info] RAID 란?
> 여러 개의 물리적인 저장 장치를 마치 하나의 저장 장치처럼 사용하도록 구성하는 기술
> 
> 장점
> - 운용 가용성, 데이터 안정성 증대
> - 디스크 용량 증설의 용이성
> - 디스크 I/O 성능 향상

### RAID 0 (스트라이핑)
![[RAID 0.png]]
- 구성 방식: 데이터를 블록 단위로 나누어 각 디스크에 분산 저장
- 최소 디스크 수: 2개
- 특징: 데이터 분산 저장 X (Parity 없음)
- 장점: 빠른 읽기/쓰기 가능
- 단점: 장애 복구 불가
	→ 디스크 하나만 고장나도 전체 데이터 손실

### RAID 1 (미러링)
![[RAID 1.png]]
- 구성 방식: 동일한 데이터를 2개의 디스크에 동일하게 저장
- 최소 디스크 수: 2개
- 특징: 데이터 복제
- 장점: 높은 데이터 안정성, 복구 용이
- 단점: 저장 효율 낮음, 비용 증가
### RAID 5 (스트라이핑 + 패리티)
![[RAID 5.png]]
- 구성 방식: 데이터와 패리티를 블록 단위로 분산 저장
- 최소 디스크 수: 3개
- 특징: 패리티 분산 저장으로 복구 가능
- 장점: 저장 공간 효율 좋음, 장애 복구 가능
- 단점: 복구 시 느림, 성능 저하 가능
### RAID 6 (RAID 5 + 이중 패리티)
![[RAID 6.png]]
- 구성 방식: 2개의 패리티를 사용해 더 높은 안정성 확보
- 최소 디스크 수: 4개
- 특징: 디스크 2개까지 장애 허용
- 장점: 매우 높은 안정성, 대규모 환경 적합
- 단점: 저장 효율 낮음, 쓰기 성능 저하

> [!info] Parity 란?
> 데이터를 복구할 수 있도록 하는 오류 검출용 중복 정보
> RAID 5, RAID 6에서 사용

- 물리 계층: Repeater(신호의 재생 및 증폭), HUB

## 네트워크 용어
### VLAN(Virtual LAN)
물리적인 하나의 LAN을 논리적으로 여러 개로 나누어 네트워크 관리

### NAT(Network Address Translation)
내부 망 → 사설 IP 주소 사용하여 통신
외부 망 → NAT를 거쳐 공인 IP 주소로 자동 변환

네트워크 주소 변환(NAT)은 IP 패킷의 TCP/UDP 포트 숫자와 소스 및 목적지의 IP 주소 등을 재기록하면서 라우터를 통해 네트워크 트래픽을 주고받는 기술

패킷에 변화가 생기기 때문에 IP나 TCP/UDP의 Check sum도 다시 계산되어 재기록해야함
### NAC(Network Access Control)
